## 動作確認

同じブラウザ・同じドメインで各サイトを開いてください。

1. TALKのハルに「みかん」を先に送る → 進みません。
2. ハルに「りんご」 → 段階1、SNS投稿が追加。招待ボタンでアオイを追加。
3. ハルに「みかん」 → 段階2、画像・SNS・ブログ・掲示板が更新。マネージャーの招待を押す。
4. アオイに「写真」 → 段階3、写真が届く。
5. マネージャーに「星座」 → 段階4、最後のブログを公開。
6. SNSに「写真」を含む投稿 → アオイが返信。アオイに「こもれび」とDM → 返信。
7. 段階2以降、星宮澪のポスト（ID: p-orange）への返信に「星座」を含める → スタッフが返信。

TALKは初回アクセス時には無言です。TALKの判定は「完全一致」「指定の言葉を含む」「どんな入力にも返信」から選べます。前後の空白は除去し、別表記は1行に1つ登録します。SNSは部分一致です。再送で段階を巻き戻したり、先に送った言葉を後で自動適用したりしません。

制作スタジオの「テスト・移行」で1分・10分・1時間・次の19時に進められます。「りんご」の1時間後と「みかん」の次の19時（日本時間）に予約返信が届きます。ランダム投稿は初回に公開時刻を抽選して保存します。再読み込みしても再抽選しません。

TALKの「進捗をリセットする」、またはスタジオの「全進捗をリセット」で、会話・SNS・会員・予約などをまとめて初期化します。テスト用のシナリオ設定は保持します。音声・管理画面のログインは各サイトのロック／ログアウトで解除します。

## 本文・ルールの編集

制作スタジオの「会話シナリオ」「発信内容」はフォームで編集できます。「このブラウザに反映」でローカル保存し、開いている別タブにも反映します。「共有用JSONを書き出す」で他の制作メンバーへ渡せます。「公開設定に戻す」でローカル変更を解除します。

全設定は `content/scenario.json`。スタジオのJSON編集から読み込み・書き出しできます。公開版を更新する場合は、書き出した内容でこのファイルを置き換え、GitHubのmainへpushしてください。ローカル下書きは他の制作者とリアルタイム共有されません。

- `contacts` / `rules`: 連絡先、キーワード、段階、複数の返信、画像、招待、予約返信。
- `accounts` / `posts` / `socialRules`: NPC情報、投稿、部分一致返信。
- `threads`: 月別スレッドとコメント。名前・uidはスレッドごとに固定。
- `blogs` / `news` / `diary`: タイトル、本文、公開条件。
- `events` / `gallery`: 会員ページの公演・写真。
- `management`: 管理パスワード、復旧ヒント、会員の架空データ。
- `recorder`: 製造番号、パスワード、録音ファイル・説明文。
- `venue`: 施設情報、定員、料金、定休日・予約不可日。

`minStep`は必要段階。`ageHours`は何時間前の投稿として表示するか。`delayMinutes`は開始／段階到達から何分後か。`randomMinutes:[4,9]`は開始から4〜9分後。IDは半角英数字・ハイフン・アンダースコアで一意にします。会話の段階は0〜100で指定でき、同じ段階への返信や分岐も可能です。初期連絡先ID `haru` は維持してください。

画像・音声は `media/` に配置し、相対パスを指定。今回の人物・建物写真は生成画像、録音はオリジナルの環境音サンプル、本文・人名・住所は仮の架空設定です。本番の台本・画像・録音に置き換えられます。

## 保存・通知・公開の前提

ゲーム状態はLocalStorage `algo-puzzle:world:v2`、ローカルシナリオは `algo-puzzle:scenario:v2`。旧試作版v1の進捗は自動で引き継ぎます。ブラウザ再起動後も保存され、タブ間で同期します。サイトデータ削除やプライベートブラウズの終了では失われます。他プレイヤーには共有されません。

ブラウザを完全に閉じている間のプッシュ通知はありません。復帰時に未配信の返信・投稿を反映します。開いている間はサイト内通知と、許可したブラウザ通知が利用できます。閉じた状態での通知にはバックエンドとWeb Pushが必要です。

GitHub Pagesのみで動く静的な謎解きアプリです。認証は演出用で、キーワード・パスワード・未公開シナリオは配信ファイルから読めます。会員パスワードはsalt付きPBKDF2で保存しますが、実サービスのアクセス制御ではありません。問い合わせ・予約はブラウザ内の体験で、外部送信・実決済はありません。制作スタジオも公開URLからアクセス可能です。本番で答えを秘匿したい場合は、判定と設定をサーバーへ移してください。

## ドメイン移行

静的ファイルをそのまま移設できます。内部リンク・画像は相対URLなのでGitHub Pagesのサブパスでも独自ドメイン直下でも動きます。連動するサイト群は同じオリジンに置き、パスで分けてください。別ドメイン間ではLocalStorageは共有できません。

1. 旧サイトのスタジオ →「テスト・移行」→「進捗を書き出す」。
2. 新サイトのスタジオ →「進捗を読み込む」→ 復元。
3. ローカル設定も必要ならシナリオJSONを別途書き出し・読み込み。

DNSやCNAMEの設定は移行先ドメインが確定してから行ってください。

## 開発

Node.js 22以降で `npm start`（http://127.0.0.1:4173）。`npm test`でエンジンと旧版互換性を確認。ビルド工程・外部APIキー・パッケージインストール不要です。`file://`では起動できません。

GitHub Pagesはmainのルートから配信します。`assets/world.js`が純粋な進行エンジン、`runtime.js`が保存と時刻同期、`assets/pages/`が各サイト、`site.css`がデザインです。旧`state.js`等はv1の検証用に残しています。

## チャット返信の設定（2026年10月更新）

制作スタジオの「会話シナリオ」で編集できます。

- 一致方法: 完全一致／指定の言葉を含む／どんな入力にも返信。
- キーワード・別表記: 1行に1つ。例として「りんご」「リンゴ」「林檎」を別々の行に記入します。登録したどれかに一致すれば返信します。
- 複数返信: 「返信を追加」で吹き出しを増やします。各返信に本文・画像・連絡先への招待を設定できます。上から順に送信します。
- 全入力への返信: 「どんな入力にも返信」に設定します。指定した連絡先と「必要な段階」でのみ有効です。空白だけの送信は無効です。
- 同じ段階で条件が重複した場合は、完全一致→部分一致→含まない→全入力→不正解の順に優先し、同種なら設定の上から1つだけ実行します。

各返信の待ち時間は、返信本文1文字につき0.2秒、最低3秒です。20文字なら4秒、画像のみなら3秒です。句読点・空白・改行も数え、結合文字や絵文字は見た目の1文字として数えます。複数返信は、直前の返信が届いてから次の返信の待ち時間を計算します。ブラウザの処理状況によって到着が少し遅れることがあります。

段階とSNS等の更新はキーワードを受け付けた時点で進みますが、一連の返信が届くまでは次のルールを受け付けません。その間の送信は履歴に残り、後から自動判定はされません。再読み込み後も未送信の返信を保持し、長時間閉じていても一斉送信せず順に届けます。リセットすると未送信の返信も取り消します。

予約返信も、指定時刻・指定時間が来てから本文に応じた待ち時間を加えます。従来の単一キーワード・単一返信のJSONも読み込めます。旧introフィールドの自動挨拶は表示しません。既存の会話履歴は削除しないため、初回の無言状態を確認するときは進捗をリセットしてください。

JSONでは `matchMode: "exact" | "contains" | "notContains" | "any" | "fallback"`、`keywords: ["りんご", "林檎"]`、`replies: [{"text":"受け取ったよ。"}, {"text":"次の手がかりです。", "image":"media/clue.svg"}]` を使用します。


## SNS・会員登録・会話分岐の追加設定（2026年10月）

### SNSアカウントと返信

STUDIOの「SNS設定」→「アカウント」で追加・編集します。表示名とIDを自由に指定でき、追加時のIDは英数字6〜16文字をランダム生成します。IDは重複不可、大文字・小文字の違いだけでも重複として扱います。検索欄は `@ID` と `ID` のどちらにも対応します。プレイヤーにも保存されるランダムIDを付けます。従来の英数字以外を含むローカル設定のIDは、読み込み時に新しいIDへ移行します。

アイコン・ヘッダー画像はPNG・JPEG・WebPをアップロードするか、`media/` 内の画像パスを指定します。アップロード画像は1枚300KB以内、シナリオ全体は2MB以内です。画像データも共有用JSONに入るので、そのJSONを渡せば別のブラウザで確認できます。画像パスを使う場合は画像ファイルも公開先に配置してください。

「SNS設定」→「自動返信」で、反応する場所・キーワード・返信文・返信アカウント・対象ポストを設定します。「特定のポストへの返信」を選び対象ポストを指定すると、その投稿へのリプライだけに反応します。対象を「すべてのポスト」にすると従来どおりです。判定は部分一致、必要な段階以降で有効です。複数条件に一致した場合はそれぞれ返信します。

SNSのポスト・リプライ・DM・お知らせには日時や「○時間前」を表示しません。ブログ等、他サイトの日時表現は維持します。

### 時間だけで公開する投稿

「発信内容」→「公開方法」で「開始からの経過時間のみ」を選び、「公開までの待ち時間」に分数を指定します。0.5なら30秒です。この方法では必要な段階を無視し、ゲーム開始（最初のアクセス／リセット）からの経過時間だけで公開します。「進捗に連動」なら指定段階に到達してからの待ち時間になります。開始時刻は保存され、再起動しても計測が続きます。閉じている間に時刻が過ぎた投稿は次に開いたときに表示します。

JSONの `publishMode: "time"` が時間のみ、`"progress"` または省略が進捗連動です。`randomMinutes` のランダム公開も引き続きJSONで設定可能です。フォームで保存するとランダム時間を外し、入力した固定待ち時間を使います。

### 入会時アンケートと会員番号

登録時に、ニックネーム・誕生日・性別・お住まいを入力します。お住まいは47都道府県と海外です。ログイン用パスワードも従来どおり設定します。

会員番号は `F + 登録日のyymmdd + 都道府県コード2桁`。登録日は端末時計に基づく日本時間で、STUDIOの早送りには影響されません。例：2026年10月19日に東京都を選んで登録 → `F26101913`。誕生日は会員番号に使いません。都道府県コードは[国土交通省のコード一覧](https://nlftp.mlit.go.jp/ksj/gml/codelist/PrefCd.html)の01〜47、海外は48です。登録後は番号を固定します。以前の登録済み会員はその番号を保持し、未回答の住所は「未登録」と表示します。

### 不正解返信・分岐・ルール名

「会話シナリオ」の一致方法に、次の2つを追加しました。

- **指定の言葉を含まない**：登録したキーワードが1つも含まれない場合に返信します。
- **他のルールに一致しない（不正解）**：その連絡先・その段階の他の条件に一致しなかった場合だけ返信します。キーワード欄は空で構いません。

不正解ルールの「必要な段階」と「返信後の段階」を同じ値にすると、進捗を進めず何度でも返信します。段階ごとに別の不正解ルールを作れば、状況に応じた返信になります。同じ段階で返信しても、その段階に到達した時刻は変わりません。

分岐の例：段階0で「赤」なら段階10へ、「青」なら段階20へ。段階10には「火」の正解と返信、段階20には「水」の正解と返信を用意します。ルールは「必要な段階」が現在と完全一致するときだけ有効です。SNS等の公開条件は従来どおり「指定段階以上」なので、分岐専用のコンテンツが必要な場合は条件設計も調整してください。

予約返信の遅延は秒単位で入力できます。指定秒数はプレイヤーの送信時点から数え、その時刻と通常返信の最後の配信予定時刻の遅い方から、本文の待ち時間（1文字0.2秒・最低3秒）を加えて届きます。既存のJSONの `minutes` も読み込めます。新しい形式は `schedule: {"type":"delay","seconds":7,"text":"予約返信"}` です。

「ルール名」を変更すると、ルール一覧にその名前を表示します。内部のIDは保存済み返信との対応を保つため維持し、制作時には好きな日本語名で見分けられます。JSONでは `name` が表示名です。

フォームを編集したら「下書きに保存」してから別の項目へ移動してください。「このブラウザに反映」「共有用JSONを書き出す」は編集中のフォームも保存します。共有用JSONを担当者に渡す運用は従来どおりで、STUDIOから全員への自動公開や同時編集は行いません。


## 返信設定の入口

- LINEの不正解返信：STUDIOの「会話シナリオ」で設定したい連絡先・段階のルールを選び、「不正解返信を設定」を押します。返信文を入力して「このブラウザに反映」を押してください。同じ段階の不正解ルールがすでにある場合は、そのルールを開きます。初期シナリオには不正解返信を入れていないため、設定していない段階では返信しません。
- SNSの返信：STUDIOの「SNS設定」→「自動返信を設定」を開きます。既存ルールを選ぶか「追加」を押し、反応する場所・対象ポスト・キーワード・返信文を設定します。「このブラウザに反映」でテストできます。初期シナリオには「写真」を含む投稿、アオイへの「こもれび」のDM、段階2以降のポストp-orangeへの「星座」の返信に対応するルールがあります。

どちらもフォームから設定でき、JSONの手編集は不要です。全員への公開は「共有用JSONを書き出す」で保存したファイルを公開担当者へ渡してください。

サイトの見出しや仮の文章は自然な日本語に書き直しました。保存済みの会話履歴やSTUDIOのローカル設定は自動で上書きしません。ローカル設定を使っている場合は、必要なJSONを先に保存してから「公開設定に戻す」で新版を確認できます。
