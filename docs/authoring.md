## 動作確認

同じブラウザ・同じドメインで各サイトを開いてください。

1. TALKのハルに「みかん」を先に送る → 進みません。
2. ハルに「りんご」 → 段階1、SNS投稿が追加。招待ボタンでアオイを追加。
3. ハルに「みかん」 → 段階2、画像・SNS・ブログ・掲示板が更新。マネージャーの招待を押す。
4. アオイに「写真」 → 段階3、写真が届く。
5. マネージャーに「星座」 → 段階4、最後のブログを公開。
6. SNSに「写真」を含む投稿 → アオイが返信。アオイに「こもれび」とDM → 返信。
7. 段階2以降、投稿への返信に「星座」を含める → スタッフが返信。

TALKのキーワードは前後空白を除いた完全一致です。SNSは部分一致です。再送で段階を巻き戻したり、先に送った言葉を後で自動適用したりしません。

制作スタジオの「テスト・移行」で1分・10分・1時間・次の19時に進められます。「りんご」の1時間後と「みかん」の次の19時（日本時間）に予約返信が届きます。ランダム投稿は初回に公開時刻を抽選して保存します。再読み込みしても再抽選しません。

TALKの「進捗をリセットする」、またはスタジオの「全進捗をリセット」で、会話・SNS・会員・予約などをまとめて初期化します。テスト用のシナリオ設定は保持します。音声・管理画面のログインは各サイトのロック／ログアウトで解除します。

## 本文・ルールの編集

制作スタジオの「会話シナリオ」「発信内容」はフォームで編集できます。「このブラウザに反映」でローカル保存し、開いている別タブにも反映します。「共有用JSONを書き出す」で他の制作メンバーへ渡せます。「公開設定に戻す」でローカル変更を解除します。

全設定は `content/scenario.json`。スタジオのJSON編集から読み込み・書き出しできます。公開版を更新する場合は、書き出した内容でこのファイルを置き換え、GitHubのmainへpushしてください。ローカル下書きは他の制作者とリアルタイム共有されません。

- `contacts` / `rules`: 連絡先、初期会話、キーワード、段階、返信、画像、招待、予約返信。
- `accounts` / `posts` / `socialRules`: NPC情報、投稿、部分一致返信。
- `threads`: 月別スレッドとコメント。名前・uidはスレッドごとに固定。
- `blogs` / `news` / `diary`: タイトル、本文、公開条件。
- `events` / `gallery`: 会員ページの公演・写真。
- `management`: 管理パスワード、復旧ヒント、会員の架空データ。
- `recorder`: 製造番号、パスワード、録音ファイル・説明文。
- `venue`: 施設情報、定員、料金、定休日・予約不可日。

`minStep`は必要段階。`ageHours`は何時間前の投稿として表示するか。`delayMinutes`は開始／段階到達から何分後か。`randomMinutes:[4,9]`は開始から4〜9分後。IDは半角英数字・ハイフン・アンダースコアで一意にします。段階は1ずつ進めます。初期連絡先ID `haru` は維持してください。

画像・音声は `media/` に配置し、相対パスを指定。今回の人物・建物写真は生成画像、録音はオリジナルの環境音サンプル、本文・人名・住所は仮の架空設定です。本番の台本・画像・録音に置き換えられます。

## 保存・通知・公開の前提

ゲーム状態はLocalStorage `algo-puzzle:world:v2`、ローカルシナリオは `algo-puzzle:scenario:v2`。旧試作版v1の進捗は自動で引き継ぎます。ブラウザ再起動後も保存され、タブ間で同期します。サイトデータ削除やプライベートブラウズの終了では失われます。他プレイヤーには共有されません。

ブラウザを完全に閉じている間のプッシュ通知はありません。復帰時に未配信の返信・投稿を反映します。開いている間はサイト内通知と、許可したブラウザ通知が利用できます。閉じた状態での通知にはバックエンドとWeb Pushが必要です。

GitHub Pagesのみで動く静的な謎解きアプリです。認証は演出用で、キーワード・パスワード・未公開シナリオは配信ファイルから読めます。会員パスワードはsalt付きPBKDF2で保存しますが、実サービスのアクセス制御ではありません。問い合わせ・予約はブラウザ内の体験で、外部送信・実決済はありません。制作スタジオも公開URLからアクセス可能です。本番で答えを秘匿したい場合は、判定と設定をサーバーへ移してください。

## ドメイン移行

静的ファイルをそのまま移設できます。内部リンク・画像は相対URLなのでGitHub Pagesのサブパスでも独自ドメイン直下でも動きます。連動するサイト群は同じオリジンに置き、パスで分けてください。別ドメイン間ではLocalStorageは共有できません。

1. 旧サイトのスタジオ →「テスト・移行」→「進捗を書き出す」。
2. 新サイトのスタジオ →「進捗を読み込む」→ 復元。
3. ローカル設定も必要ならシナリオJSONを別途書き出し・読み込み。

DNSやCNAMEの設定は移行先ドメインが確定してから行ってください。

## 開発

Node.js 22以降で `npm start`（http://127.0.0.1:4173）。`npm test`でエンジンと旧版互換性を確認。ビルド工程・外部APIキー・パッケージインストール不要です。`file://`では起動できません。

GitHub Pagesはmainのルートから配信します。`assets/world.js`が純粋な進行エンジン、`runtime.js`が保存と時刻同期、`assets/pages/`が各サイト、`site.css`がデザインです。旧`state.js`等はv1の検証用に残しています。
